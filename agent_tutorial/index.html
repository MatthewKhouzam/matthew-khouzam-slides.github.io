What is an Agent?

  • An LLM that can take actions, not just generate text
  • It has a loop: observe → think → act → observe…
  • It uses tools to interact with the real world
  • It decides which tools to call and when
The key difference between a chatbot and an agent is the ability to take actions. An agent doesn't just tell you what to do — it does it.

Agent vs Chatbot

ChatbotAgent
OutputTextText + Actions
ToolsNoneFile I/O, shell, APIs, MCP…
LoopSingle turnMulti-step reasoning
AutonomyAnswers questionsSolves problems
A chatbot answers. An agent acts. That's the fundamental shift.

Anatomy of an Agent

System Prompt (personality, rules, constraints)
↓
LLM (reasoning engine)
↓
Tools (file read/write, shell, MCP servers…)
↓
Environment (your filesystem, APIs, databases)
Every agent has these four layers. The system prompt shapes behavior, the LLM reasons, tools provide capabilities, and the environment is what gets acted upon.

MCP — The Tool Layer

  • Model Context Protocol — open standard by Anthropic
  • Lets agents call external tools via JSON-RPC
  • Write a tool once → use it from any MCP-compatible agent
  • Gemini CLI, Kiro CLI & Goose all support MCP
Agent
→
MCP Server
→
Your Tool / API
MCP is the universal adapter. You write a server that exposes tools, and any agent can use them.

Writing an MCP Server (Python)

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("my-tools")

@mcp.tool()
def greet(name: str) -> str:
    """Say hello to someone."""
    return f"Hello, {name}!"

@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

if __name__ == "__main__":
    mcp.run()

Install: pip install mcp

This is a complete MCP server. Two tools, 15 lines. The docstrings tell the AI what each tool does.

Wrapping a CLI Tool as MCP

import subprocess
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("git-tools")

@mcp.tool()
def git_log(n: int = 5) -> str:
    """Show recent git commits."""
    return subprocess.run(
        ["git", "log", f"-{n}", "--oneline"],
        capture_output=True, text=True
    ).stdout

if __name__ == "__main__":
    mcp.run()

Any CLI program → MCP tool in 5 lines.

This is the key insight. Any command-line tool can become an MCP server with a thin Python wrapper. subprocess.run is all you need. The docstring tells the AI when to use it.

Part 1: Gemini CLI

Google's open-source AI agent in your terminal

Let's start with Gemini CLI — Google's take on a terminal-based AI agent.

Gemini CLI: Setup

# Install
npm install -g @anthropic-ai/gemini-cli
# or
npx @anthropic-ai/gemini-cli

# Authenticate (uses Google account)
gemini
  • Open source (Apache 2.0)
  • Uses Gemini 2.5 Pro by default
  • 1 million token context window
Gemini CLI is installed via npm. First run authenticates with your Google account.

Gemini CLI: Creating an Agent

Create GEMINI.md in your project root:

# Agent Instructions

You are a code review assistant.

## Rules
- Always check for security issues first
- Suggest fixes, don't just point out problems
- Be concise

## Tools Available
- You can read and write files
- You can run shell commands
- You can use git

GEMINI.md = the system prompt for your agent

GEMINI.md is the personality file. It tells the agent who it is and how to behave. It's checked into your repo so the whole team shares the same agent.

Gemini CLI: Enabling MONCEF

Add the prompt to GEMINI.md and configure in .gemini/settings.json:

{
  "customAgents": [{
    "name": "moncef",
    "configPath": "moncef.json"
  }]
}

Then invoke it:

gemini --agent moncef
In Gemini CLI, you reference the agent config from settings.json and select it with the --agent flag. Same agent, different plumbing.

Gemini CLI: Adding MCP Tools

Create .gemini/settings.json:

{
  "mcpServers": {
    "my-tools": {
      "command": "python3",
      "args": ["mcp_server.py"]
    }
  }
}

Now the agent can call greet and add from our MCP server.

Point Gemini CLI at your MCP server and it automatically discovers the tools. The agent decides when to use them based on the user's request.

Gemini CLI: Built-in Extensions

  • Automatic file read/write and shell execution
  • Google Search integration
  • Customizable safety thresholds
  • Sandbox mode for untrusted operations
# Run with sandbox
gemini --sandbox

# Use a specific model
gemini --model gemini-2.5-flash
Gemini CLI comes with batteries included. File I/O and shell are built in. You add MCP for domain-specific tools.

Part 2: Kiro CLI

Amazon's AI agent for the terminal

Now let's look at Kiro CLI — Amazon's approach to the same problem.

Kiro CLI: Setup

# Install
npm install -g kiro-cli

# Start
kiro-cli chat
  • Uses Claude (Anthropic) as the LLM
  • Built-in code intelligence (LSP integration)
  • Subagent delegation for parallel tasks
Kiro CLI is installed the same way. It uses Claude under the hood and has some unique features like LSP integration and subagents.

Kiro CLI: Creating an Agent

Create .kiro/settings/agent.md:

# Agent Instructions

You are a code review assistant.

## Rules
- Always check for security issues first
- Suggest fixes, don't just point out problems
- Be concise

Same idea as GEMINI.md — a markdown file defines the agent's behavior.

Kiro uses a similar pattern. A markdown file in the .kiro directory defines the agent's personality and rules.

Kiro CLI: Enabling MONCEF

Drop the config into .kiro/agents/:

cp moncef.json .kiro/agents/moncef.json

Then invoke it:

kiro-cli chat --agent moncef

allowedTools restricts which built-in tools the agent can access.

In Kiro, agents live in the .kiro/agents directory. You select one with the --agent flag. The allowedTools field acts as a security boundary.

Kiro CLI: Adding MCP Tools

Create .kiro/settings/mcp.json:

{
  "mcpServers": {
    "my-tools": {
      "command": "python3",
      "args": ["mcp_server.py"]
    }
  }
}

Same MCP server, different config location. That's the beauty of MCP.

Exact same MCP server, just a different config file path. This is why MCP matters — write once, use everywhere.

Kiro CLI: Unique Features

  • Code Intelligence — LSP-powered symbol search, go-to-definition, find references
  • Subagents — delegate tasks to parallel workers
  • Planner Mode — Shift+Tab to switch to read-only planning
  • AWS Integration — native AWS CLI tool access
Kiro's differentiators are code intelligence and subagents. The LSP integration means it actually understands your code structure, not just text.

Part 3: Goose

Block's open-source AI agent — MCP-native

Goose is Block's open-source agent. Its key differentiator: everything is an MCP server, even built-in tools.

Goose: Setup

# Install
brew install block/goose/goose
# or
curl -fsSL https://github.com/block/goose/releases/latest/download/install.sh | sh

# Start
goose session
  • Open source (Apache 2.0)
  • Supports multiple LLMs (OpenAI, Anthropic, Google…)
  • Everything is an MCP extension
Goose is model-agnostic — you pick your LLM. And its architecture is pure MCP: even built-in capabilities like file I/O are MCP servers.

Goose: Enabling MONCEF

Drop the config into .goose/recipes/:

cp moncef.json .goose/recipes/moncef.json

Then invoke it:

goose session --recipe .goose/recipes/moncef.json

Same JSON format as Kiro and Gemini — just a different path.

Goose also supports the same agent JSON config. Drop it in .goose/agent.json and it just works. Same pattern across all three CLIs.

Goose: Adding MCP Tools

Create .goose/recipes/mcp.json:

{
  "mcpServers": {
    "my-tools": {
      "command": "python3",
      "args": ["mcp_server.py"]
    }
  }
}

Same MCP server, same JSON format — Goose treats it as just another extension.

In Goose, MCP config lives in .goose/recipes/mcp.json. Same format as the others. Write once, use everywhere.

The Pattern: Building Any Agent

  1. Define behavior — write a system prompt (markdown file)
  2. Add tools — write MCP servers for domain-specific capabilities
  3. Configure — point the CLI at your MCP servers
  4. Iterate — refine the prompt based on agent behavior

This pattern works for any MCP-compatible agent.

Regardless of which CLI you use, the pattern is the same. System prompt plus MCP tools equals an agent.

Tips for Good Agents

  • Tool docstrings matter — the AI reads them to decide what to call
  • Keep tools focused — one tool = one action
  • Return structured text — helps the AI parse results
  • System prompt = guardrails — be explicit about what the agent should and shouldn't do
  • Test with edge cases — agents are creative in unexpected ways
The quality of your agent depends more on good tool design and clear prompts than on which LLM you use.
