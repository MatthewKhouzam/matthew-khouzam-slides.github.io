What is MCP?

Standardized protocol for LLM-tool integration

MCP is Anthropic's open protocol that standardizes how LLMs interact with external tools and data sources. Think of it as a universal adapter that lets AI assistants access databases, APIs, file systems, and other resources in a consistent way.

MCP 2.0 Security Improvements

March 2026 release addresses critical gaps

MCP 2.0 was released in March 2026 with major security improvements. Let's look at what was fixed and what still needs attention.

What's Fixed in 2.0

  • ✅ OAuth 2.1 Authorization: Built-in auth framework with PKCE
  • ✅ Tool Annotations: Describe behavior (read-only, destructive)
  • ✅ Dynamic Client Registration: Automatic OAuth client setup
  • ✅ JSON-RPC Batching: Improved performance and efficiency
  • ✅ Streamable HTTP Transport: More flexible than HTTP+SSE
MCP 2.0 adds comprehensive OAuth 2.1 authorization with PKCE for secure authentication. Tool annotations let servers describe whether tools are read-only or destructive. Dynamic client registration removes friction. JSON-RPC batching improves efficiency. And the new streamable HTTP transport is more flexible than the old HTTP+SSE approach.

Still Requires Attention

  • ⚠️ Tool Execution: Sandboxing still implementation-dependent
  • ⚠️ Tool Poisoning: Annotations must be treated as untrusted
  • ⚠️ Audit Logging: No standardized audit framework
  • ⚠️ Transport Encryption: HTTPS required but not enforced
  • ⚠️ Scalability: Token bloat and latency issues in production
However, several issues remain. Tool execution sandboxing is still up to implementers. Tool annotations help but must be treated as untrusted unless from verified servers. There's no standardized audit logging framework. And while HTTPS is required, it's not protocol-enforced. Additionally, real-world testing shows MCP can consume 20x more tokens than REST endpoints, creating scalability challenges for production agents. These need implementation-level solutions.

Advanced Attack Vectors (Persist in 2.0)

  • Rug Pulls: Benign servers turn malicious after trust
  • Cross-Server Shadowing: Malicious tools mimic legitimate ones
  • Preference Manipulation: Persuasive metadata biases selection
  • Namespace Typosquatting: Similar names trick users
Despite 2.0 improvements, sophisticated attack patterns remain. Rug pulls occur when a trusted server is updated with malicious code after deployment. Cross-server shadowing exploits multi-server environments where attackers register tools with identical names to intercept calls. Preference manipulation uses psychological tactics in tool descriptions to bias AI selection - tool annotations help but don't eliminate this. And typosquatting leverages similar-looking server names to fool users during installation.

Scalability Challenges

Production deployment considerations

Before diving into solutions, let's understand the scalability challenges that emerge in production deployments. These aren't theoretical - they're based on real-world testing and enterprise feedback.

Token Economics Problem

  • 20x Overhead: 20,000 tokens (MCP) vs 1,000 (REST) in testing
  • Model Lock-in: Forces expensive frontier models
  • Latency Impact: More tokens = longer processing
  • Cost at Scale: Prohibitive for high-volume operations
Real-world testing reveals significant token overhead. Converting natural language to SQL with Couchbase MCP required 20,000 tokens for context about collections and relationships. The same task via REST? Around 1,000 tokens. This 20x difference forces organizations to use expensive frontier models instead of efficient small language models. More tokens mean longer processing times, creating latency issues in dynamic agentic networks. At scale, you're paying for infrastructure overhead instead of AI reasoning.

Agent Type Matters

Coding Agents ✅

  • Exploratory work
  • Complex reasoning
  • Many possible tools
  • Overhead justified

Production Agents ⚠️

  • Routine automation
  • Latency-sensitive
  • High-volume operations
  • Cost-conscious
The fit varies dramatically by agent type. Coding agents like Claude Code handle complex, exploratory tasks requiring deep reasoning. They need access to many tools and understand sophisticated schemas. When you're doing development work, MCP's overhead is justified - you're optimizing for capability, not speed. But production organizational agents are different. Customer service automation, task routing, and data updates need to be lightweight, fast, and cost-effective at scale. They're latency-sensitive components in dynamic networks where MCP's architecture becomes a fundamental mismatch.

MCP-T: Enhancing the Standard

Solving scalability without fragmentation

Rather than creating a competing standard, Huawei developed MCP-T as an enhancement layer. This approach maintains ecosystem compatibility while addressing the performance and scalability concerns we just discussed.

MCP-T Key Features

  • Token Optimization: Intelligent caching reduces context overhead
  • Performance Layer: Addresses latency for production agents
  • Backward Compatible: Works with existing MCP servers
  • Enterprise Focus: High-volume, production deployments

Enhancement approach preserves ecosystem while solving production gaps

MCP-T tackles the scalability issues head-on. Token optimization through intelligent caching reduces the 20x overhead problem. A performance layer addresses latency concerns, making it viable for production organizational agents. Critically, it maintains backward compatibility - you're not choosing between standards, you're enhancing what exists. The focus is enterprise production use cases where MCP alone struggles. This demonstrates that the identified limitations are solvable within the existing framework.

Deployment Strategy

  • Coding Agents: Standard MCP (Claude Code, exploratory work)
  • Production Agents: MCP-T or direct REST APIs
  • Skills: Behavioral guidance, lightweight setup
  • Hybrid: Mix approaches based on requirements
The deployment strategy becomes clear. Use standard MCP for coding agents doing exploratory work where capability matters more than speed. For production organizational agents, evaluate MCP-T for enhanced performance or use direct REST APIs for maximum efficiency. Use Skills for behavioral guidance in stable contexts. The key insight: don't let momentum drive architecture. Choose based on actual requirements - agent type, latency needs, volume, and cost constraints. Enhancement approaches like MCP-T show you don't have to choose between ecosystem compatibility and production performance.

Privacy & Compliance Gaps

Hidden data exposure risks

Beyond security, there are significant privacy concerns. These are particularly important for enterprises dealing with sensitive customer data or operating under strict regulatory requirements.

Key Privacy Risks

  • Sensitive data in context windows
  • Unencrypted server-client communication
  • Third-party server trust issues
  • GDPR compliance unclear
  • Data residency requirements violated
Sensitive data gets embedded in context windows and may be sent to third-party LLM providers. Not all MCP implementations use encryption. You're trusting third-party MCP servers with your data. From a compliance perspective, it's murky - GDPR compliance isn't well-defined for MCP implementations, and data residency requirements may be violated when using cloud-based LLMs.

MCP Server Lifecycle

Understanding the complete operational journey

To properly secure MCP, we need to understand its complete lifecycle. Academic research has identified four distinct phases, each with unique security considerations.

Four Phases & Four Threat Types

Lifecycle Phases

  • Creation: Metadata, capabilities
  • Deployment: Publishing, installation
  • Operation: Runtime execution
  • Maintenance: Updates, auditing

Threat Actors

  • Malicious Developers: Poisoning, backdoors
  • External Attackers: Spoofing, injection
  • Malicious Users: Credential theft, escape
  • Security Flaws: Vulnerable versions
Each phase has distinct security requirements. Creation involves defining what the server does. Deployment is when it enters the ecosystem. Operation is runtime execution. Maintenance covers ongoing updates. Research identifies four attacker types - malicious developers create compromised servers, external attackers exploit deployment vulnerabilities, malicious users abuse operational features, and security flaws arise from poor maintenance. Each requires different defensive strategies.

Enterprise Challenges

  • Integration: Legacy systems, custom auth, network conflicts
  • Governance: No standard policy enforcement
  • Discovery Gap: Unknown servers in environment
  • Architecture: No centralized security oversight
  • Multi-tenant: Isolation challenges
  • Production Scalability: Token costs force expensive models
For enterprises, integration is challenging. Legacy systems weren't designed for this. There's no standard way to enforce policies. CISOs report a critical discovery gap - they don't know what MCP servers exist in their environment. Research highlights fundamental gaps - there's no central authority to enforce security baselines, and multi-tenant deployments lack proper isolation. Beyond security, production scalability is a major concern. MCP's token overhead forces organizations to use expensive frontier models for simple tasks that could run on efficient small language models with direct APIs. This architectural limitation significantly impacts operational costs at scale.

Recommended Mitigations

Security Controls

  • Sandboxing: Isolated execution (DB: SELECT only, Files: restricted dirs)
  • Input Validation: Strict parameter checking
  • Audit Logging: Comprehensive activity tracking
  • Tool Verification: Cryptographic signatures
  • GraphRAG: Context-aware authorization
The good news is there are mitigations. Sandboxing isolates tool execution - for example, database servers limited to SELECT queries only, file servers restricted to specific directories. Strict input validation prevents injection attacks. Comprehensive audit logging gives you visibility. Tool verification helps detect poisoned or malicious MCP servers. And GraphRAG provides context-aware authorization using knowledge graphs. These aren't optional - they're essential.

Lifecycle-Specific Defenses

  • Creation: Automated metadata verification, capability validation
  • Deployment: Reproducible builds, cryptographic signatures
  • Operation: Runtime sandboxing, session management
  • Maintenance: Automated updates, continuous auditing
Research shows defenses must align with lifecycle phases. During creation, automate metadata generation and validate capabilities. At deployment, use reproducible builds and verify signatures. During operation, enforce sandboxes and manage sessions. In maintenance, automate version control and conduct continuous security audits.

Enterprise Best Practices

  • Phased rollout in controlled environments
  • Internal MCP server hosting
  • Role-based access control (RBAC)
  • MCP server inventory and monitoring
  • End-to-end encryption + PII detection
  • Use case assessment: MCP for coding, REST for production agents
For enterprise deployment: start with a phased rollout in controlled environments. Host your own MCP servers internally rather than relying on third parties. Implement proper RBAC. Maintain an inventory of all MCP servers to address the discovery gap. Use end-to-end encryption and implement PII detection and automatic redaction. Critically, assess use cases carefully - deploy MCP for coding agents and exploratory work where its capabilities shine, but use direct REST APIs for production organizational agents where token efficiency and latency matter. Don't let momentum drive architecture decisions.

The USB of AI

MCP promises to be the universal connector for AI agents

And I think it delivers - it covers many use cases well

But remember: USB didn't replace everything

PCIe, SATA, SAS, RAM slots, RS-232, PS/2, HDMI, DisplayPort, 3.5mm audio, LVDS, SMBus, I2C, SPI, ISA... they all still exist for good reasons

MCP promises to be the USB of AI - a universal connector that simplifies integration. And I think it delivers on that promise. It covers many use cases well, especially for coding agents and exploratory work. But here's the key insight: USB didn't replace everything. We still have PCIe for high-performance graphics and storage. SATA and SAS for drives. RAM slots for memory. RS-232 for industrial equipment. PS/2 for legacy systems. HDMI and DisplayPort for high-bandwidth video. 3.5mm audio jacks. LVDS for displays. SMBus, I2C, and SPI for embedded systems. Even ISA in some legacy industrial applications. Each exists because it's optimized for specific requirements. The same will be true for AI agent integration. MCP is excellent for many scenarios, but direct APIs, enhancement layers like MCP-T, and other approaches will coexist. Choose the right connector for your requirements. Universal doesn't mean exclusive. Thank you.
